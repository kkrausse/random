# Browser workspace decision matrix

Criteria run down the left; approaches run across the top. Cells describe mechanisms, requirements, and what is known
or unknown. There are no scores, rankings, pass/fail labels, or colors. Evaluation can be added as a separate step.

This is one wide table so each criterion can be compared across all approaches. QEMU directly and container2wasm/QEMU
are separate columns to expose integration differences even though they use the same emulator family.

Evidence as of 2026-09-05: [source notes](assessment.md#evidence-and-limitations) and the linked upstream research in
[plan.md](plan.md). “Documented” means an upstream claim, not a result from our fixture. No workload has been benchmarked.
“Not established” identifies missing evidence rather than an assertion that the capability is absent.
