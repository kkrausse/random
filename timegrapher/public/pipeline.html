How the timegrapher calculates rate and amplitude

This documents the complete implementation pipeline from microphone samples to the displayed seconds/day, seconds/day error, and amplitude.

microphone PCM
↓ mono audio
↓ high-frequency band-pass filters
↓ transient features at 8192 Hz
↓ rolling analysis window
├─→ nominal BPH → adaptive fine-fold search → measured BPH → seconds/day + error
└─→ two-beat folded waveform → lift time → amplitude

1. Microphone capture

Code: public/main.ts:320–380. Microphone constraints: lines 336–343. Audio graph: lines 345–380.

The browser requests an audio stream with these processing options disabled:

  • Echo cancellation
  • Noise suppression
  • Automatic gain control

These are browser constraints, not guarantees. The operating system or microphone hardware may still process the signal. The stream is connected to an audio worklet. The worklet output passes through a zero-gain node so the microphone is processed but not played through the speakers.

Convert to mono

Implementation: feature-worklet.ts:111–125.

For every PCM frame, all microphone channels are averaged:

mono sample = sum of channel samples / channel count

Detect transients

Implementation: feature-worklet.ts:96–100, 127–134.

For each filtered band:

  1. Take the absolute value of the filtered sample.
  2. Track a fast envelope with a 2 ms time constant.
  3. Track a slow envelope with an 80 ms time constant.
  4. Subtract the slow envelope from the fast envelope.
  5. Clamp negative results to zero.
novelty = max(0, fast envelope − slow envelope)

This suppresses steady background sound and emphasizes the leading edges of watch sounds.

Reduce to 8192 feature frames per second

Feature clock: feature-worklet.ts:93, 136–142. Compression and batching: feature-worklet.ts:148–188.

The feature rate is the smaller of 8192 Hz and the microphone sample rate. Between two feature frames, the processor keeps the maximum novelty value, then compresses it:

feature = log(1 + 100 × maximum novelty)

At 8192 Hz, adjacent feature frames are about 0.122 ms apart. Features are sent to the analysis worker in batches of 2048 frames, or about 0.25 seconds.

The program first chooses among these standard watch rates:

14400, 18000, 19800, 21600, 25200, 28800, or 36000 BPH

For every candidate BPH, its two-beat cycle duration is:

cycle seconds = (3600 / candidate BPH) × 2

Each frequency band is folded into this repeating cycle. In other words, all samples at the same phase of different cycles are accumulated together. The standard-selection fold uses 64 phase bins.

phase = (sample time modulo cycle seconds) / cycle seconds

The fold reduces bins whose energy is inconsistent between cycles. Each folded band is then normalized to zero mean and unit standard deviation.

The candidate is scored by looking for two strong sound packets separated by half a cycle: one tick and one tock. The two strongest band scores are added together. The candidate with the highest score becomes standardBph.

This is categorical selection: for example, “this is approximately a 28,800 BPH movement.” It is not yet the precision rate measurement.

5. Score a precise fold candidate

Candidate folding: tracking-fold-fit.ts:205–226. Fold scoring: tracking-fold-fit.ts:91–182.

Relevant configuration

PEAK_WINDOW_SECONDS0.15 msSets the radius used to collect peak energytracking-fold-fit.ts:46, 96–99

For every trial BPH, each frequency band is folded independently into a 4096-bin two-beat cycle. The normal cycle-coherence adjustment remains enabled.

Each folded band is scored as follows:

  1. Smooth the bins over the configured packet width.
  2. Subtract the row mean and clamp negative values to zero.
  3. Calculate a moving sum of positive energy around every possible peak position.
  4. Pair every position with the position half a cycle away.
  5. Use the weaker member of each tick/tock pair, then retain the strongest pair.
band score = strongest paired energy² / total positive energy

Using the weaker side prevents a loud tick with no corresponding tock from scoring well. Dividing by total energy penalizes diffuse noise. The trial BPH score is the sum of the two strongest band scores.

On the first update—or whenever nominal BPH changes—the search is centered on standardBph with a 300 BPH radius. On later updates it is centered on the previous measured BPH and uses the current confidenceBph as its radius.

trial BPH = center BPH + confidence BPH × offset

All 21 trial values are folded and scored using the process above. Initially, the points are 30 BPH apart. As confidence shrinks, the same 21 points cover a progressively finer range. Every trial is still clamped to 300 BPH above or below the nominal rate.

7. Interpret the score curve

Curve tests: tracking-fold-fit.ts:228–332. Candidate selection: tracking-fold-fit.ts:375–384.

The tracker does not blindly accept the largest score. It handles three cases:

  1. Best point is at a search edge. If it beats the center by both 5% and 0.25 score units, the edge is selected and the next search radius expands by 1.4. If not, the center remains selected.
  2. Best point is an interior point. It is selected if it beats the center. The next radius only shrinks when it also forms one clear, isolated peak.
  3. The center ties or beats the apparent best point. The center is retained and the next search radius expands by 1.1.

A peak counts as clear only when all of these checks pass:

  • It exceeds both immediate neighbors by the prominence ratio and margin.
  • Exactly one prominent peak is competitive with the best score.
  • The curve has no more than two significant rises while moving away from the peak.
  • It beats both search edges by the required drop ratio and margin.

The selected trial is temporally smoothed before display:

measured BPH = previous measured BPH × 0.25 + selected BPH × 0.75

The first measurement after nominal BPH changes is not smoothed. The search radius is multiplied by the curve decision's scale, then clamped between 0.1 and 300 BPH. This updated radius becomes confidenceBph and controls the next update's trial spacing.

9. Convert measured BPH to seconds/day

Code: public/main.ts:253–278; the seconds/day formula is on lines 255–258.
seconds/day = (measured BPH / standard BPH − 1) × 86400

Example:

standard BPH = 28800
measured BPH = 28802
seconds/day = (28802 / 28800 − 1) × 86400 = +6.0

A positive result means the watch is running fast. A negative result means slow.

The value labeled “error” is the fold tracker's current adaptive search radius, confidenceBph. It starts at 300 BPH. A clear score peak repeatedly multiplies it by 0.7; ambiguous curves generally leave it unchanged or expand it; and a strong edge hit multiplies it by 1.4. It is clamped from 0.1 to 300 BPH.

That is converted to seconds/day:

seconds/day error = BPH error / standard BPH × 86400

For a 28,800 BPH watch, the 0.1 BPH floor produces:

0.1 / 28800 × 86400 = ±0.3 seconds/day
Meaning of this error: it describes how narrowly the fold-search algorithm has converged. It is not a measured standard deviation, a calibrated confidence interval, or a bound on real-world accuracy. It does not include systematic microphone, clock, classification, or amplitude-model error.

Amplitude uses the same transient features, but not the individually selected beat times. All frequency bands are added together and folded into a 4096-bin two-beat cycle at standardBph.

Amplitude uses nominal standardBph, not precision measuredBph.

Find the main tick and tock peaks

Implementation: analysis-worker.ts:231–263, 380–411.

The folded cycle is split in half. The maximum bin in the first half becomes the main tick impulse; the maximum bin in the second half becomes the main tock impulse.

seconds per fold bin = two-beat cycle seconds / 4096

For 28,800 BPH:

two-beat cycle = 0.25 seconds
seconds per fold bin = 0.25 / 4096 = about 0.061 ms

This fold spacing is finer than the original 0.122 ms feature-frame spacing. Folding does not create new timing information.

Find the preceding acoustic event

Implementation: analysis-worker.ts:265–327, 342–378.

For tick and tock independently, the program:

  1. Smooths the fold over approximately 0.25 ms.
  2. Searches backward from the main peak through 12% of one beat.
  3. Requires a preceding event to reach at least 8% of the main peak.
  4. Prefers the earliest qualifying local maximum.
  5. Falls back to the earliest threshold crossing or strongest qualifying point.

The separation from that preceding event to the main impulse is the lift time:

lift seconds = absolute offset in bins × seconds per fold bin

The UI calls this “unlock/drop.” More precisely, the implementation measures the time from a detected preceding acoustic lump to the main folded peak.

Convert lift time to amplitude

Formula: analysis-worker.ts:329–340. Tick/tock averaging: analysis-worker.ts:412–429. Lift-angle UI configuration: main.ts:176–184, 283–293.

Let:

  • L = configured lift angle in degrees, 52° by default
  • t = detected lift time in seconds
  • C = two-beat cycle duration in seconds
amplitude in degrees = L / (2 × sin(π × t / C))

Tick and tock amplitude are calculated separately. The displayed amplitude is their arithmetic mean. If only one side produces a result, that one result is displayed.

12. Interpretation limits

Result data model: public/data.ts:87–123. Worker result assembly: analysis-worker.ts:617–642.
  • No uncertainty or error value is calculated for amplitude.
  • Amplitude depends directly on the configured lift angle.
  • The code assumes that the detected preceding sound corresponds to the physical unlock event; it does not independently verify that assumption.
  • A large rate offset can smear amplitude because amplitude folds at nominal BPH.
  • The rate error describes fold-search convergence, not guaranteed absolute accuracy.
  • All values describe only the current rolling window, six seconds by default.
