# Browser feasibility spike / functional Kings Beach v0

2026-09-27. Scope: browser application and independent, reproducible OSM graph adapter. The other agent owns the Organic Maps generator/audit; this report does **not** assert native pipeline reuse.

## What works

- Static Vite/React/Effect v4 app, no runtime server API. One prepared 1,104,370-byte JSON region is bundled with the installable production app. Source: OpenStreetMap contributors via Overpass (`https://overpass.kumi.systems/api/interpreter`), OSM base timestamp `2026-07-15T15:22:01Z`; raw response SHA-256 `539d3f785c5d840cccc9e4d98007fa43131eb3b0d75ec8467fdf070ca29a1461`, exact bbox/query in package. ODbL attribution in app and data.
- 1,180 OSM ways, 8,829 nodes, 9,042 consecutive-node edges. All original way tags and available node tags retained; links identify way and both OSM nodes. Graph contains routable classes only; ways intersecting the bounded query can extend outside it. This is not a complete map database (relations, restriction members, area polygons, elevations, closures, and non-selected highways are missing).
- Browser worker runs bounded shortest-path variations and deduplicates by edge overlap; returns locally generated loops and exact reversed out-and-backs. Default Kings Beach connected trail start, 3–9 km hiking: 12 loops / 8 out-and-backs, without padding to 20. Numeric sortable results and selected-route framing, map click to change start, route-edge click to inspect all raw tags, hiking/gravel and shape/distance inputs.
- Every route's traveled distance includes repetitions; unique edge distance separately reported. Motorcycle, bicycle, motor vehicle buckets each independently sum to route length, so these attributes overlap rather than partition. Explicit tags override inferred classification; missing evidence stays unknown. Footway/steps imply foot access and cycleway implies bicycle access, **not** a verified ban on other modes. Private/no access is excluded for own travel, unknown is not treated as confirmed permission. Conditional/destination/customer access is conservatively excluded for the user's mode. No traffic or physical separation observation exists. `electric_bicycle` tags, if present, survive raw retention but have no special interpretation yet.
- Production service worker precaches the shell, hashed app JS/CSS, worker, region, manifest, icon; static host only. Assets are replaceable and personal-data durability is not implemented.

## Organic Maps browser consumption feasibility

Upstream [structure](https://github.com/organicmaps/organicmaps/blob/master/docs/STRUCTURE.md) places generator in C++/Python and routing/indexer/storage in C++ with native platform I/O; [maps_generator README](https://github.com/organicmaps/organicmaps/blob/master/tools/python/maps_generator/README.md) describes `.mwm` sections for rendering/search/routing and requires compatible generator/app releases. There is no demonstrated browser-ready `.mwm` reader or WASM router here. A credible direct path requires pinning a revision, cross-compiling the required native storage/indexer/routing dependency closure, replacing platform file I/O with browser random-access or a virtual FS, matching binary section versions/classificator/resources, exposing coarse graph/attribute/query bindings, and proving retained raw OSM evidence. Downloading an `.mwm` into a browser and reading bytes alone would not establish any of those. WASM size, runtime memory, and actual build feasibility are **unmeasured**. Do not claim native `.mwm` reuse or even MWM-exported graph reuse from this v0. This custom adapter is an independently prepared fallback proving browser-local graph traversal and display only; await the native agent's audit before any architecture decision.

## Honest gaps before routing advice

- Sparse query yields a bounded neighborhood, not a regional Tahoe package. SVG map is topological linework with no offline basemap, terrain, labels, or proper trailhead anchoring; clicking arbitrary nodes may select disconnected fragments. Route suggestions have not had human quality/safety review. Dijkstra edge costs and overlap threshold are provisional.
- No turn restriction relations, conditional access parser, barrier traversal detail, mode-specific oneway exceptions, boundary clipping, elevation/grade, separated cycleway evidence, observed use, seasonal closure, private parcel context, or cross-region stitching. Access classification is intentionally conservative but incomplete, including country-specific legal defaults. Gravel profile rejects steps rather than offering dismount. Default loop can include some road connector mileage and should not be used for navigation.
- No import UI or versioned atomic region update/checksum verification at install, OPFS/IndexedDB catalog, backups/saved routes, GPX, location, or phone test. The manifest embeds source SHA but app does not verify graph bytes against a package hash. Static package replacement must update SW cache version when republishing. No shell/data available offline until first production visit and SW install finishes; browser eviction can remove cache. Explicit import, update rollback, and durable personal-data storage remain future work.
- UI uses Base UI Select, Tailwind, Lucide and largely default/native controls rather than generated shadcn component files. No Organic Maps license obligations are triggered by this separate implementation, but OSM ODbL attribution and adapted-database duties still apply to distribution.

## Reproduction / tests

`bun install`, `bun run prepare:region [archived-response]`, `bun test`, `bun run build`, `bunx vite preview --host 127.0.0.1 --port 4173`. Bun tests assert real OSM metadata/topology and route continuity, deterministic identities, exact reversed out-and-back repetition, access evidence buckets, explicit/inferred/unknown interpretation and incompatible format rejection. Typecheck is part of build. Fixture graph could supplement real-data tests for unusual turn and barrier cases when modeled. Re-run browser offline test after every service-worker change.
