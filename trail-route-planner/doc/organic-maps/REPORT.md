# Organic Maps generator spike — 2026-09-27

**Result:** A real pinned generator compiled and emitted a small Kings Beach `.mwm` with geometry, spatial/search indexes, routing and road-access sections. A separately version-bound companion export recovered OSM way tags (including motorcycle and e-bike) by final feature ID. This **does not** yet prove point-to-point routing, a useful full Tahoe region, a browser reader, or acceptable package size. Do not choose the final architecture from this run alone.

## Retention audit (source at pinned revision)

`OsmElement` → `generator/osm2type.cpp` and `generator/osm2meta.cpp` → intermediate `FeatureBuilder` → `generator/feature_sorter.cpp:282–301` final feature ID; auxiliary collectors independently serialize road access/restrictions before `BuildRoadAccessInfo` maps way IDs to feature IDs (`generator/road_access_generator.cpp:490–585,717–737`). Runtime consumes the routing graph and access via `libs/routing/index_graph_loader.cpp` / `libs/routing/road_access.cpp`; feature types and metadata are accessible via `FeatureType`. The *absence* of a road-access entry is not evidence of permission: runtime `RoadAccess` has its own default/fallback semantics (`libs/routing/road_access.cpp:84–106`), which must not be presented as explicit OSM evidence.

## Modification and format options

`export-way-evidence.py` is a working **companion attribute modification**: reads the generator's actual V1 `.osm2ft`, reads the exact XML, writes per-feature source way ID/version/timestamp/**unmodified tag dictionary** and MWM/XML SHA-256. A lookup of feature `109` returns way `800853245` and the motorcycle/e-bike evidence above. Its 24-byte record decoding depends on upstream `std::pair<CompositeId,uint32_t>` little-endian ABI and checks magic/version/count/byte size; validate against an upstream C++ reader before production. The mapping's other composite ID and node/point splitting remain to be modeled. If a source way splits, the same way evidence is copied to both output feature IDs; a future segment key should be `(dataset version, feature ID, point index, direction)` with node/barrier/condition data separately.

- **Extend stock metadata / roadaccess:** integrates with native runtime but requires C++ enum/serialization, generator and mobile/runtime compatibility updates, and probably a distinct motorcycle/e-bike mode; raw evidence and ambiguity still need explicit modeling. Existing metadata enum says append values only (`libs/indexer/feature_meta.hpp:54–60`).
- **Custom MWM section:** can key feature ID and be read by native/WASM, but needs new section writer/reader, upgrade policy, and full app compatibility checks; not implemented.
- **Companion:** implemented here, easiest versioning and browser parsing; uncompressed all-way JSON is ~3.6× the tiny `.mwm`, so filter relevant ways/tags and compare compressed binary/columnar encodings on a useful area. Validate both hashes together before activation. Keeping `.osm2ft` as a separate ~51 KiB build artifact is optional after export, not a runtime ID solution by itself.

## Gate, dependencies, remaining work

The upstream Python orchestrator (`tools/python/maps_generator/README.md`) is designed for named countries and PBF/o5m conversion; direct `generator_tool` XML flags are a narrower reproducible path for this tiny case, **not** a full regional PBF build. Acquire a geographically useful CA/NV extract (e.g. source PBF + `osmium extract` with complete references), immutable timestamp/checksum, proper custom country metadata/border, then repeat. Build/test actual A→B routing using matching native runtime; enumerate route segment feature+point IDs and join evidence. Build and test cross-MWM if regions split; use actual target phone/browser for offline WASM/export graph, memory/storage/latency/cancellation measurements. Browser proof belongs to the parallel prototype, not this report. A decision between MWM+WASM, reusing preparation with browser export, and a small dedicated pipeline is **open**.

This spike did not finish a dependency-by-dependency distribution inventory; do not distribute packages based on this audit alone.
